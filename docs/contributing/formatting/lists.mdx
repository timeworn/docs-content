---
title: Lists
description: Guidelines for creating and using lists.
---

Lists make related information easier to scan. Use a list when there are at
least two related items. Introduce a list with a complete sentence and keep each
item grammatically consistent.

## Bulleted Lists

Use bullets when the order does not matter.

```mdx
Before installing the bot, make sure you have:

- A Discord account
- A GitHub account
- The **Manage Server** permission
```

> Before installing the bot, make sure you have:
>
> - A Discord account
> - A GitHub account
> - The **Manage Server** permission

Keep each item in the same grammatical form. Do not mix fragments and complete
sentences.

## Numbered Lists

Use a numbered list when the order matters.

```mdx
1. Open **Settings**.
2. Select **Repositories**.
3. Select **Connect Repository**.
4. Choose the repository you want to connect.
```

> 1. Open **Settings**.
> 2. Select **Repositories**.
> 3. Select **Connect Repository**.
> 4. Choose the repository you want to connect.

Use the `Steps` component when each step needs its own heading, image, or
explanation. See [Built-In Components](../fumadocs/components.mdx).

## Nested Lists

Use nested lists when there is a relationship between items.

```mdx
- Windows
  - Windows 10
  - Windows 11
- Android
  - Android 12 or later
```

> - Windows
>   - Windows 10
>   - Windows 11
> - Android
>   - Android 12 or later

Avoid more than three levels. Deeply nested lists are hard to read and should be
separated into different sections.

## Checklists

Use a checklist when the reader needs to complete a series of tasks.

```mdx
- [x] Test each command.
- [ ] Check every link.
- [ ] Preview the page on a small screen.
```

> - [x] Test each command.
> - [ ] Check every link.
> - [ ] Preview the page on a small screen.

Do not use checklists for instructions or steps.

## Punctuation

Use a period when every item is a complete sentence. Fragments do not need a
period unless they are long or contain multiple sentences.
